# 规格是新的源代码

在我的职业生涯里，规格越写越短。我刚进 Microsoft 时，衡量一个 PM 价值的标准是规格的厚度。多年以后，在 Tripadvisor ，我们把那位把一份写在餐巾纸上的规格带进产品评审会的 PM 传为美谈。

产品团队常常把规格当成文书工作 —— 在“真正的交付工作”之前不得不忍受的坏事。工程师因优雅的代码受到赞扬，设计师因漂亮的用户体验受到赞扬。 PM 则因交付影响力而获得赞许。但规格呢？它们通常被草草了事、被丢到一边、被遗忘。

这一直是个错误。在我的[产品能力工具包 ](https://www.ravi-mehta.com/product-manager-skills/)里，“功能规格”排在首位 —— 十二项能力中的第一项 —— 这是有原因的。它与产品交付、产品质量一起，支撑着产品执行。

无懈可击的执行是优秀产品管理的基石，而一份出色的规格就是起跑线。
