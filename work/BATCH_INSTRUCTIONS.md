## 硬性要求（违反即判失败，会被机器质检拦下）

- **R1 结构逐块对齐**：标题层级、段落数、列表项数、表格行列数必须与原文完全一致。
  不许合并或拆分段落，不许增删内容，不许调整顺序。
- **R2 代码一字不动**：``` 围栏代码块、行内 `` `代码` ``、命令、URL、文件路径、变量名、
  API 名全部逐字节原样保留（含代码里的英文注释）。
- **R3 链接地址不动**：`[文字](URL)` 只译文字，URL 一字不改。
- **R4 术语严格按表**：用 glossary.json 的 `zh` 定译；`forbid` 里的写法一个都不能出现；
  `keep:true` 的词保留英文。
- **R5 中英文之间加空格**：「使用 Claude Code」✅ ｜「使用Claude Code」❌
- **R6 中文用全角标点**：，。；：？！（）；但代码、URL、英文内部的标点保持原样。
- **R7 不留成串未译英文**（专有名词、命令行、图表标签、坐标轴除外）。
- **R8 不加译者注、不写「注：」、不删内容。**
- **R9 表格逐格翻译，行列数不变。**
- **R10 只改文字，不改编排。**

## 已知的结构陷阱（前几批踩过，务必照做）

1. **讲义幻灯片的列表是「两行式」**：`- ` 单独占一行，内容在下一行，末尾还常带一行
   页脚（如 `themodernsoftware.dev`）。必须**逐行 1:1 保留**，绝对不要合并成一行。
2. **`N) (Optional) ...` 这类有序列表**：原文用半角 `)`。中文写成「2）（可选）…」或
   「2) （可选）…」都可以，关键是**保留列表项形式**，不要写成普通段落。
3. **`## Slide N` / `## Page N` 分页标记原样保留**，不翻译、不改编号 —— 它们是定位锚点。
4. **纯人名 / 产品名组成的幻灯片页**：按 spec 第 4 节保留英文即可，不要硬译。
5. **无正文的文件**（如 `requirements.txt`、样例数据 `api_docs.txt`）：内容本就是
   依赖清单或代码，保留原样即为正确，不算漏译。

## 关于「提示」这个词

`prompt` 作**名词**时统一译「提示词」。但 prompting 的动名词译法在中文里就是「提示」：
「零样本提示」「思维链提示」「少样本提示」「自洽性提示」「多轮提示」「角色提示」——
这些都是**正确写法**，不要改成「…提示词」。质检脚本已经不再误报。

每译完一份，运行：

```

术语一致率为 100%）。有问题就自己改到通过为止。
该命令只写 `work/qa_<slug>.json`，不会影响全局报告。
