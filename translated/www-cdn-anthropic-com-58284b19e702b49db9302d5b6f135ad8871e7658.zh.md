面向数据基础设施的 Claude Code
数据基础设施团队负责为全公司各团队整理所有业务数据。他们用 Claude Code 自动化例行的数据工程任务、排查复杂的基础设施问题，并编写有文档记录的工作流，让技术与非技术团队成员都能独立地访问和操作数据。
Claude Code 的主要用例
用截图调试 Kubernetes
当 Kubernetes 集群宕机、无法调度新 Pod 时，团队用 Claude Code 诊断问题。他们把仪表盘的截图喂给 Claude Code，后者带着他们逐个菜单地走完 Google Cloud 的
界面，直到发现一条警告，指出 Pod 的 IP 地址已耗尽。随后 Claude Code 给出了创建新 IP 池并将其加入集群的确切命令，无需再请网络专家介入。
面向财务团队的纯文本工作流
团队向财务团队成员演示了如何编写描述自身数据工作流的纯文本文件，再把这些文件加载进 Claude Code，实现全自动执行。没有编程经验的员工也能描述诸如「查询这个仪表盘、获取信息、运行这些查询、产出 Excel 输出」这样的步骤，Claude Code 会执行整个工作流，包括主动询问日期这类必需的输入。
帮助新员工导航代码库
当新的数据科学家加入团队时，会被告知用 Claude
Code 来浏览他们庞大的代码库。Claude Code 会读取他们的
Claude.md 文件（文档），为具体任务找出相关文件，解释数据流水线的依赖关系，并帮助新人理解哪些上游数据源供给到仪表盘。这取代了传统的数据目录与可发现性工具。
会话结束时
团队会在每项任务结束时请 Claude Code 总结已完成的工作会话并提出改进建议。这形成了一个持续改进的回路：Claude Code 会依据实际使用情况帮助打磨 Claude.md 文档与工作流说明，使后续迭代更有效。
跨多个实例的并行任务管理
处理耗时的数据任务时，他们会在不同项目的不同仓库中打开多个 Claude Code 实例。每个实例都保留完整的上下文，因此几小时或几天后切回来时，Claude Code 仍清楚记得他们在做什么、做到哪里，从而实现真正的并行工作流管理，且不会丢失上下文。

Claude Code 的主要用例
用自动接受模式快速做原型
工程师通过启用「自动接受模式」（shift+tab）并搭建自主循环来快速做原型：Claude 在其中编写代码、运行测试并持续迭代。他们会把不熟悉的抽象问题交给 Claude，让它自主工作，然后在自己接手做最终完善之前评审这个完成度 80% 的方案。
团队强调要从未被污染的 git 状态开始，并定期提交检查点，这样一旦 Claude 偏离方向，就能轻松撤销错误的改动。
核心功能的同步编码
对于涉及应用业务逻辑的更关键功能，团队与 Claude Code 同步协作，给出带有具体实现说明的详细提示词。他们会实时监控整个过程，确保代码质量、风格指南合规与架构正确，同时把重复性的编码工作交给 Claude。
构建 Vim 模式
他们最成功的异步项目之一是为 Claude Code 实现 Vim 键位绑定。他们让 Claude 构建整个功能（尽管这并非优先事项），最终实现中大约 70% 来自 Claude 的自主工作，只需几轮迭代就完成了。
测试生成与缺陷修复
他们用 Claude Code 在实现功能之后编写全面的测试，并处理拉取请求评审中发现的简单缺陷修复。
他们还利用 GitHub Actions 集成，让 Claude 自动处理拉取请求评论中的问题，例如格式问题或函数重命名。
代码库探索
面对不熟悉的代码库（例如 monorepo 或 API 一侧）时，团队用 Claude Code 快速理解系统如何运作。他们不再等 Slack 回复，而是直接向 Claude 询问解释和代码引用，省下了大量切换上下文的时间。

面向安全工程的 Claude Code
安全工程团队关注的是保障软件开发生命周期、供应链安全和开发环境安全。他们大量使用
Claude Code 来编写和调试代码。
Claude Code 的主要用例
复杂基础设施调试
处理事故时，他们会把堆栈追踪和文档喂给 Claude Code，让它沿着代码库追踪控制流。这显著缩短了生产问题的解决时间，原本需要人工扫读代码 10-15 分钟的问题，现在大约 5 分钟就能理解。
Terraform 代码评审与分析
对于需要安全审批的基础设施变更，他们把
Terraform 计划复制进 Claude Code，问「这会造成什么结果？我会不会后悔？」这形成了更紧密的反馈回路，让安全团队更容易快速评审并批准基础设施变更，减少开发流程中的瓶颈。
文档整合与运行手册
他们让 Claude Code 读取多个文档来源，生成 markdown 运行手册、故障排查指南和总览。
他们把这些浓缩后的文档当作上下文来调试真实问题，比在完整知识库中检索更高效。
测试
他们不再沿用过去「设计文档 → 粗糙的代码 → 重构 → 放弃写测试」的模式，而是先向 Claude Code 要伪代码，引导它做测试驱动开发，并定期检查、在它卡住时纠正方向，最终得到更可靠、更可测的代码。
上下文切换与项目上手
在参与「dependant」这类既有项目（一个用于安全审批工作流的 Web 应用）时，他们用 Claude Code 编写、评审并执行以 markdown 撰写、存放在代码库中的规格，从而在几天而不是几周内就做出有意义的贡献。
